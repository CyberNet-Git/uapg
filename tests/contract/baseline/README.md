# Эталон контракта uapg 0.2.15

Эти файлы сняты с реализации **0.2.15** (`main`, коммит `18df1cf`) до начала
переписывания и служат приёмкой для новой реализации: публичный API и схема БД
обязаны совпадать, иначе `opc-vibro-iot-server` и существующие базы сломаются.

| Файл | Что в нём |
|---|---|
| `api.json` | Сигнатуры всех публичных методов `HistoryTimescale` и `HistoryTimescaleV2`, состав `uapg.__all__`, публичные атрибуты, полные наборы ключей `get_performance_metrics()` / `get_cache_stats()` / `get_connection_info()` |
| `schema_core.json` | Схема после `HistoryTimescale.init()`: шесть таблиц ядра, индексы, гипертаблицы, политики ретенции |
| `schema_v2.json` | Схема после `HistoryTimescaleV2.init()` в режиме `dual`: дополнительно миграции 001–004 и 101–102, функции `uapg_*`, CAGG `uapg_events_hourly` |
| `wire.json` | Формат данных: `variantbinary` и колонка `value` для каждого типа Variant, кодирование `events_history.event_data`, сквозной проброс старых строк без префикса `base64:`, числовые значения `StatusCode` |

Ключи метрик — часть контракта: из них строятся имена узлов OPC UA
(`write.variables.queue_size` → `WriteVariablesQueueSize`), поэтому переименование
ключа тихо ломает адресное пространство сервера.

**Пересоздавать эти файлы нельзя.** `tests/contract/capture_baseline.py` импортирует
`uapg` из рабочего дерева: запуск после переписывания снимет контракт с нового кода
и превратит проверку в тавтологию. Осознанные отступления фиксируются списком
исключений в самих тестах, а не правкой эталона.
